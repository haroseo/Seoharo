# Cokform

> 원하는 대로, 콕 묻고 받아요.

Cokform(콕폼)은 한국 실무 환경에 맞춘 폼 서비스 프로젝트다. 신청, 채용, 행사, 교육, 커뮤니티, 피드백 수집을 대상으로 질문을 만들고 응답을 받은 뒤 운영 작업까지 이어지는 흐름을 단순하게 만드는 것을 목표로 했다.

이 문서는 Cokform의 **정본 보존 문서**다. 브랜드, 제품 방향, 기능 범위, 디자인 원칙, 보안·개인정보 기준, 배포·복구 기록, 현재 상태를 한곳에서 확인할 수 있도록 정리한다. 상세한 UI 토큰과 화면 규칙은 [`Design.md`](./Design.md)를 기준으로 한다.

---

## 1. 현재 상태

Cokform은 2026-10-10부터 신규 기능 개발을 중단하고 **유지보수·보존 모드**로 전환했다. 사업 확장을 목적으로 운영하지 않으며, 포트폴리오의 앱·웹 개발 사례로 보존한다.

| 항목 | 상태 |
|---|---|
| 제품 개발 | 신규 기능 동결 |
| 운영 | 치명적 장애·보안·데이터 복구만 대응 |
| 브랜드 자료 | 보존 완료 |
| 디자인 자료 | 보존 완료 |
| 제휴 제안서 | 보존 완료 |
| 사용자 데이터 | 이 아카이브에 포함하지 않음 |
| 운영 비밀값 | 이 아카이브에 포함하지 않음 |
| 공개 코드 기준점 | `haroseo/Seoharo`의 `main` |
| 보존 태그 | `cokform-preservation-20261010` |
| 보존 커밋 | `chore: preserve Cokform assets` |

이 저장소의 `archives/cokform/`은 운영 서버나 데이터베이스의 대체물이 아니다. 실제 운영을 재개해야 하는 경우, 별도 Cokform 저장소와 별도 환경을 먼저 만들고 이 문서와 PDF만 참고 자료로 사용한다.

## 2. 프로젝트 정체성

### 2.1 서비스 정의

- 국문명: 콕폼
- 영문명: Cokform
- 한 줄 설명: 한국 실무 흐름에 맞춘 개인정보 보호형 폼 빌더
- 슬로건: **원하는 대로, 콕 묻고 받아요.**
- 핵심 가치: 자유도, 명확함, 실무성, 복구 가능성, 개인정보 보호
- 브랜드 성격: 친근하지만 가볍지 않음, 신뢰감 있지만 딱딱하지 않음

“콕”은 귀엽게 꾸민다는 의미가 아니라, 필요한 지점을 정확히 집어 묻고 다음 일까지 이어간다는 의미다. 기능 수를 자랑하기보다 작성자·응답자·운영자의 흐름을 끊지 않는 것을 우선한다.

### 2.2 주요 사용자

- 폼을 만드는 사람: 질문과 조건을 빠르게 구성하고 수정해야 한다.
- 응답하는 사람: 모바일에서도 내용을 잃지 않고 제출해야 한다.
- 운영하는 사람: 응답 상태, 알림, 필터, 내보내기, 복구를 확인해야 한다.
- 협력 조직: 채용·행사·교육·커뮤니티 신청을 제한된 범위에서 파일럿 운영한다.

### 2.3 대상 사용 사례

채용 지원서, 연락처 수집, 행사 신청, 교육 신청, 커뮤니티 가입, 파티 초대, 프로젝트 지원, 만족도 조사, 피드백 접수, 공공·비영리 조직의 실무형 신청서가 주요 사례다.

## 3. 제품 범위와 보존된 설계 방향

Cokform이 지향했던 핵심 흐름은 다음과 같다.

1. 폼 목적과 개인정보 수집 여부를 먼저 정한다.
2. 질문 제목·설명·필수 여부·입력 형식을 구성한다.
3. 선택값에 따라 필요한 질문만 보여준다.
4. 응답자는 새로고침·탭 전환·일시적 네트워크 문제에도 초안을 잃지 않는다.
5. 작성자는 응답을 한 사람 단위의 맥락으로 확인한다.
6. 운영자는 검색·필터·개별 삭제·휴지통·내보내기·복구를 사용한다.
7. 버전과 백업을 통해 변경 전 상태로 돌아갈 수 있다.

검토되었던 기능 범위에는 조건부 질문, 개인정보 수집 고지, 이메일 기록 여부, 응답 기간과 마감, 응답 재개, 응답자별 보기, 금칙어, 장난 응답 완화, 알림, CSV·엑셀·이미지·프레젠테이션 내보내기, Google Drive 연동, 모바일 최적화, 자동 저장, 휴지통, 버전 복구가 포함된다. 이 목록은 현재 운영 기능이 모두 활성화되어 있다는 의미가 아니라, 프로젝트에서 다뤘던 제품 요구사항의 기록이다.

## 4. 기술·배포 기록

과거 설계 및 배포 맥락은 다음과 같다.

- 프론트엔드: React 18 기반 UI
- 번들·개발: Vite
- 스타일: Tailwind CSS 및 프로젝트 CSS 토큰
- 아이콘: Lucide React
- 배포 후보: Cloudflare Pages
- 데이터베이스·인증 후보: Supabase
- 문서 PDF: Typst 기반 CJK 최적화 출력
- 라우팅: pathname 기반 커스텀 라우팅을 사용했던 구조
- 주요 화면: 홈, 소개, 리소스, 브랜드 가이드, 디자인 가이드, 개인정보 처리방침, 이용약관, 국외이전, 서비스 이용 제한

과거 배포·검토에서 모바일 390px 레이아웃, PDF 접근성, SEO·OG 이미지, 로그인 리다이렉트, Google OAuth, Supabase RLS, 백업·복구, 응답 데이터 유실 방지, 편집기 자동 저장과 새로고침 복구를 주요 점검 대상으로 삼았다.

현재 이 아카이브에는 운영 소스, 데이터베이스 덤프, Supabase 키, OAuth 비밀값, 사용자 응답 원문, 백업 복호화 키를 보존하지 않는다.

## 5. 개인정보·보안 원칙

Cokform은 개인정보를 수집하는 도구이므로 “절대 안전”, “해킹 불가”, “법적 책임 없음” 같은 표현을 사용하지 않는다. 보호 범위와 운영 책임을 정확히 구분한다.

- 폼 운영자는 수집 목적·항목·보유 기간·파기 방법·문의 방법을 직접 정한다.
- 수집이 필요한 항목만 받고, 필요하지 않은 개인정보는 받지 않는다.
- 개인정보 안내는 폼 안에서 응답 전에 확인 가능해야 한다.
- 동의가 필요한 경우 목적과 항목을 분리해 명확하게 표시한다.
- 운영자 권한과 응답자 권한을 분리한다.
- 데이터베이스 접근은 RLS와 최소 권한을 기준으로 한다.
- 서비스 키, DB URL, OAuth secret, 암호화 개인키는 Git에 저장하지 않는다.
- 백업은 운영 데이터와 분리하고, 복호화 키는 저장소와 다른 위치에 보관한다.
- 삭제·초기화·마감은 확인 단계와 복구 경로를 함께 제공한다.
- 장애나 데이터 손실이 발생하면 원인과 복구 시점을 기록한다.

법률 문서는 서비스 구현과 운영 환경에 따라 달라질 수 있으므로 실제 재개 시 최신 법령과 전문가 검토를 다시 진행한다.

## 8. Git·백업 기준

현재 Git 기준점은 `haroseo/Seoharo`다. Cokform 자료는 `archives/cokform/` 아래에 격리되어 있으며 포트폴리오 저장소의 다른 앱·웹 코드와 섞지 않는다.

- 보호된 기본 브랜치: `main`
- 작업 방식: 별도 브랜치 → 검증 → Pull Request → 병합
- 보존 태그: `cokform-preservation-20261010`
- 보존 커밋: `969859f`
- 로컬 Git bundle: `Seoharo-main-cokform-preservation-20261010.bundle`

Git에는 코드와 문서만 둔다. 사용자 데이터와 비밀값은 암호화 백업 체계로 별도 관리한다.

## 9. 변경·복구 절차

### 문서만 수정하는 경우

1. `main`에서 직접 수정하지 않는다.
2. `docs/cokform-*` 또는 `chore/cokform-*` 브랜치를 만든다.
3. 민감정보 검색과 Markdown 검사를 수행한다.
4. 변경 내용을 Pull Request로 올린다.
5. 병합 후 태그 또는 커밋 해시를 이 문서에 기록한다.

### 운영 재개가 필요한 경우

1. Cokform 전용 비공개 저장소와 새 배포 환경을 만든다.
2. 기존 사용자 데이터가 필요한지 먼저 확인한다.
3. 암호화 백업의 무결성과 복호화 가능성을 별도로 검증한다.
4. 인증·RLS·백업·복구·삭제 정책을 새 환경에서 다시 테스트한다.
5. 개인정보처리방침과 약관을 최신 상태로 검토한다.
6. 제한된 비공개 파일럿 후 공개 여부를 결정한다.

이 아카이브만으로 사용자 응답 데이터를 복구할 수 없다. 사용자 데이터 복구는 별도 암호화 백업과 백업 키가 모두 있어야 한다.

## 10. 종결 선언

Cokform의 확장 개발은 종료한다. 이 문서와 `Design.md`, PDF 자료는 프로젝트의 의도·설계·브랜드·운영 판단을 잃지 않기 위한 포트폴리오용 정본이다.

새로운 에너지는 앱·웹 개발 포트폴리오에 사용한다. Cokform은 필요할 때 기술·제품·디자인 사례로 설명할 수 있는 상태로만 유지한다.
