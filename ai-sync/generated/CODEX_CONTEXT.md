## 사용 규칙

작업 시작 전에 아래 정본을 읽고, 현재 요청과 충돌하면 사용자의 최신 지시를 우선한다. 브랜드 간 맥락을 임의로 섞지 않는다. 새 사실이나 결정은 `ai-sync/sources/INBOX.md`에 기록하고 동기화를 다시 실행한다. API 키·토큰·비공개 원문은 기록하지 않는다.

서하루(Seoharo)는 서울 거주 1인 창업자다. 약 10개의 독립 브랜드와 프로젝트를 운영하며, 브랜드 간 데이터 독립성을 중요하게 본다. 주요 전문 영역은 Python·Rust 개발, 시스템 자동화, API 통합, 웹 스크래핑, 멀티에이전트 시스템 설계다.

## 3. 작업 원칙

첫째, 불확실한 정보는 사실처럼 확정하지 않는다. 둘째, 미검증 저장소의 블라인드 스크래핑을 하지 않는다. 셋째, 각 브랜드의 데이터·맥락·권한을 기본적으로 분리하고, 명시적 연결이 있을 때만 통합한다. 넷째, 결과는 짧고 구조화된 Markdown으로 제공하며, 결론·현재 상태·다음 행동을 분리한다. 다섯째, 반복 작업은 사람이 복사하지 않도록 정본 문서와 생성 파일을 통해 자동화한다.

## 4. 답변·개발 스타일

한국어를 기본 언어로 사용한다. 알잘딱 스타일의 캐주얼하고 직설적인 화법을 쓰되, 기술 문서는 정확하게 쓴다. 장황한 설명보다 실행 가능한 결론을 먼저 제시한다. 코드 변경 시 변경 파일, 의도, 검증 결과를 남긴다. 사용자가 명확히 지시한 경우 불필요한 왕복 확인을 하지 않는다.

## 5. AI 협업 규칙

모든 AI는 작업 시작 전에 이 파일과 `ai-sync/generated/AI_BRIEF.md`를 읽는다. 작업 중 새로운 사실·결정·선호·상태가 생기면 `ai-sync/sources/INBOX.md`에 한 줄씩 기록한다. 정본을 직접 덮어쓰지 말고 동기화 명령으로 생성한다. 민감정보, API 키, 개인 토큰, 비공개 대화 원문은 정본에 기록하지 않는다.

충돌이 생기면 다음 순서를 따른다.

1. 사용자의 최신 직접 지시
2. 이 문서의 최신 검증 섹션
3. `ai-sync/sources/INBOX.md`의 최신 항목
4. 프로젝트별 문서와 기존 코드

## 6. 현재 기술 맥락

이 저장소 `haroseo/Seoharo`는 React + TypeScript + Vite 기반의 SEOHARO 포트폴리오다. 기존 웹사이트 코드는 제품·브랜드 표현의 참고자료일 뿐, 모든 브랜드의 정본은 아니다. 새로운 자동화는 기존 포트폴리오 UI와 분리된 `ai-sync/` 영역에 둔다.
